# 设计与验证边界

## 重置事务

会话级并发闸 → 活度检查 → 有序释放目标运行时并等待写句柄关闭 → fork → 独立读回核验完整事件前缀 → 归档备份 → 持久化交接包与账本 → 隔离旧实体 → 同ID重建并写一轮交接 → 独立读回校验 → DONE。

- `lib/session-lifecycle.js` 针对已验证的 AgentLoop/Cordis 布局，定位唯一的 `agentLoop.scope(id)` 有序 disposer。依赖宿主 effect 元数据，未知形状、身份变化或运行中状态会拒绝修改存储。
- 并发闸覆盖目标会话的输入、创建、准备与恢复入口，其他会话可继续工作。
- `lib/backup.js` 将 fork 的持久化事件前缀与原事件逐项比较。备份大小、行数相近不能代替该核验。
- `lib/agent-preset.ts` 从正式投影/持久化选择事件读取原预设。执行请求可选 `agentPreset`，省略沿用原预设；指定时用宿主 `agentPresets.resolve()` 在释放前校验，并在隔离前复检。创建同ID会话时显式传入已解析ID，独立读回必须匹配。近期采样与模型候选共享此路径，失败始终恢复原预设。
- `lib/reset-transaction.ts` 组织执行与显式恢复；`lib/reset.js` 只保留既有导入入口。
- `lib/reset-journal.ts` 在 `session-reset/transactions/<operationId>/` 原子发布不可变清单，记录原路径、SHA-256、字节数和文件数。每步状态写入新的事件文件并fsync；隔离原件位于 `quarantine/<operationId>/original/`。
- 恢复根据实际位置与摘要识别“重命名已完成、事件未写入”的中断窗口。原位出现的新实体先移至 `preserved/<generationId>/`，再恢复原件。回迁再次失败仍保留已完成步骤，下一次恢复跳过已校验回迁的实体，冲突时拒绝覆盖。
- `lib/ledger.ts` 保留旧账本和损坏尾部，每次插件装载使用新的追加文件，逐条fsync。历史记录缺损会显示提示；事务清单与事件承担恢复判断。
- 只有新日志中实际存在完整交接文本且轮次符合约定，才持久化 `committed` 并返回 verified DONE；随后历史账本追加失败只返回提示，不能反过来撤销已提交事务。

## 评估连接

`lib/evaluation-settings.ts` 复用 DSH 凭证服务，按配置档派生专用记录地址，地址和Key在同一记录内原子更新。普通配置文件只需要保留插件设置，密钥不进入源码、模型上下文、报告或读接口。

首次自定义或跨域更换服务要求明确输入Key；留空仅保留当前记录中的Key，不向自定义域名回落发送默认环境凭证。URL限定HTTP(S)，拒绝内嵌凭证、查询与片段，请求不跟随重定向。

每次预览解析一次连接，全部筛选和核对请求共用该连接。后续操作重新解析，连接的私有摘要参与缓存键；保存清空旧缓存。读接口只返回地址、配置状态与可写性。

## 候选主题与会话查询

先提供由该会话当前模型生成的候选主题，再让用户采用或编辑续接目标。`lib/session-model.ts` 从同一观察切片的正式`modelSelection.next`视图读provider/model/reasoningEffort，仅next=null时使用agentDefaultModel；缺失或过期投影拒绝，未知路由不改用其他模型。`ctx.llm.prepareCall()`绑定宿主适配器和配置，单次调用不携带原会话ID、不挂载工具；仅使用完整stop回执的文本，不接纳思考或工具块。

`lib/topic-analysis.ts` 取全部直接用户消息和最近8条助手回复，最多64批并行提取，必要时分层合并，最多96次宿主模型调用。候选标题/目标是生成建议，每条必须选择输入中存在的来源ID；原文由服务端按ID读取，模型生成的引文不进入显示，兼容旧格式时也只取其ID。节选按Unicode码点截取并标记，不改写源文。汇总层只能复用输入已有来源ID。原文范围、覆盖、模型和并行峰值随报告保存。不能把该材料覆盖冒充整份会话的语义覆盖。

`lib/topic-previews.ts` 复用定点observeSession及既有消息投影，网络调用前释放lease。模型和源摘要参与8份进程内缓存，最多2份主题任务同时运行；内容/模型变化拒绝旧候选，适配器拓扑变化中止在途主题任务。选择主题只填目标，后续仍由既有Jev筛选/核对和独立确认执行。

已核对用户提供的[SQLite FTS5查询文档](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/session-query/session-query-sqlite/README.zh.md)和本机0.2.1-rc.2类型。该包已随基础组合安装，基础组合openAt=never；全文搜索用于字面token召回，不生成主题，unicode61也不保证中文子串召回。filterEvents/readSurface/readEvent的精确读取会回放完整日志，不在批次间重复调用。保留已有observeSession的精确cut/冷缓存/惰性事件，不另建SQLite、不改索引开关、不把搜索命中当完整历史。未来检索也只通过sessionQuery公共接口并限定目标会话，不打开其派生数据库。

## 采样预览

从一致的宿主观察切片借用冻结事件，使用正式消息投影得到当前可见文本；网络评估开始前释放观察lease。原始调度流水不进入候选集。

展开已识别的历史交接并保留历史引用标记，限制展开深度。候选输入在最多64批内受数量和UTF-8体积约束：每批上下文≤32片段/48KB，包含首尾和最近直接用户消息锚点；片段只评分一次，最多192次模型请求，实际完成即停止。筛选和核对共用的额度由原8批/16次提高，避免千级片段在核对前因固定上限停止；容量边界之外、调用中断后未提交的批次、输出预算遗漏均分别记录，不把计划送评数当完成覆盖。

`lib/continuation-context.ts` 把续接目标和任务/约束/纠正清单显式化。默认范围是接续全部未完成任务，允许用户填写更具体目标，但其他主题未闭环线索及持续约束仍要保留。目标只用于筛选，不增加权限，经过既有脱敏后进入请求、缓存和报告。

先用既有布尔评估协议分批提取原文线索，汇总全局清单，再在相同全局原文上判定任务闭环/约束撤销线索。没有新增自由生成模型或依赖；助手自述和历史引用不能成为新增授权，状态标记只是模型推断。所有清单原文都先保留，不直接据闭环判断删除。清单限定16KB共享输入预算，超过预算、分类/状态灰带、覆盖或闭环核对不完整均停止通过，不截断原件。

每个后续筛选/核对批次携带同一份冻结清单，来源+对应引文+共享清单受48KB合计约束。清单引用ID得到程序级优先保留与执行复核；模型仍按本批来源ID核对引用，其他清单ID在所属来源批检查，避免把分批缺席误判成全局遗漏。

`lib/handoff-batches.ts` 以最多4个worker并行执行同一阶段的批次；筛选全部收口后才并行核对。结果槽位绑定原始批次索引，乱序回执不影响来源顺序或最低概率聚合，也不能用非本批ID的答案覆盖其他批次。错误后停止新派发、等待在途请求收口，只有成功且格式合法的回执增加完成批次及评分覆盖。

第一阶段分批并行按有业务价值排序的0–3级判据评估必要性，同时识别后续纠正；以保留等级2/3的合计概率做三态路由。灰带保留原文。第二阶段从同一候选交接包切出与本批来源ID对应的引文，按来源+引文合计≤48KB拆细核对，避免反复发送整份大候选触发提供方token上限；全部来源都须核对完毕，否则保持pending。保留逐批trace，三项显示值取各批最低值，要求每批都通过；它不是全局联合概率。如果筛选遗漏上下文导致核对未通过，且完整送评原文能入预算、无概率灰带并有剩余请求额度，最多改成全量原文候选再逐批核对一次。原评分、首次核对和最终核对均保留，最终状态仅按最终候选全部判据计算；不重复相同候选、不选取两次结果中的较高值。

模型本身没有重置、执行命令或发布的权限。用户明确选中完整通过的候选、输入短ID后，独立的 `sessionResetExecuteModel` 接口才进入既有重置事务。`lib/model-previews.ts` 保持最多8份进程内缓存，运行中的任务不因旧缓存淘汰而丢失。`sessionResetModelPreviewStart(sessionId)` 保持原默认范围入口；新增 `sessionResetModelPreviewStartWithGoal({sessionId,continuationGoal})` 创建或接回显式目标任务，`sessionResetModelPreviewStatus({sessionId,taskId})` 只读进度，必须同时匹配会话与任务ID。阶段、真实完成批次、在途请求、并行上限4、请求消耗及评分覆盖均由后台维护；结束后返回同一报告。旧同步预览接口仍等待同一任务。最多2份预览同时运行，插件网络请求总上限8。报告、当前连接私有摘要、目标体积、续接目标及源投影摘要共同绑定候选。配置变更清缓存，缓存丢失后不从历史报告JSON恢复执行资格。

`lib/model-handoff.ts` 在会话闸内、目标运行时已释放后，对同一备份观察切片重新构造源投影，核对报告ID、源摘要/游标、明确续接目标、全局清单摘要与逐条原文身份、采样/判据版本、完整覆盖、三项门槛、原文与来源、预算和种子一致性。失败在fork和隔离前拒绝，不降级到近期采样。通过后原样保存version4候选种子：原文加标明scopeOnly的筛选目标/清单来源索引，闭环判定和概率不写成续聊事实。回执与事务记录带报告ID和源摘要，执行不增加模型调用。Typed output仍不是事实真值，合成样例不证明真实长历史准确率。

## 接口与客户端

`lib/remote-service.ts` 使用宿主自己的 `TypertRemoteService` 挂载插件拥有的 `sessionReset` 服务，不再给 `workspaceRegistry` 添加方法或依赖残留绑定。当前接口为 `/api/sessionReset/<method>`，方法名保持 `sessionResetDryRun`、`sessionResetExecute`、`sessionResetResume`、`sessionResetModelPreview`、`sessionResetEvaluationSettings`、`sessionResetSaveEvaluationSettings`、`sessionResetRecoveryStatus`、`sessionResetRecoveries`，独立的 `sessionResetExecuteModel`，以及只读任务入口 `sessionResetModelPreviewStart` / `sessionResetModelPreviewStartWithGoal` / `sessionResetModelPreviewStatus`，以及候选主题任务入口 `sessionResetTopicPreviewStart` / `sessionResetTopicPreviewStatus`。

宿主自动TYPERT loader按包名长期缓存基础接口清单。当前自动入口只发布空清单，本包已导出的 `/preview` 子模块贡献拥有上述接口。旧版缓存的 `workspaceRegistry` 贡献保持原拥有者，新命名空间与之并存；卸载仅移除自己的服务和贡献，不重载全局缓存。

`src/client.ts` 是浏览器单一源码；`tools/build-client.ts` 生成 `lib/client.js`，`tools/build-package.ts` 将所有发行入口编译到 `dist/*.js` 并改写 `.ts` 相对导入。普通 `node_modules` 安装不再依赖 Node 类型擦除。

续接目标输入前展示候选主题数量、紧凑单选列表及实际分析模型。所有标题优先同屏，选中后才显示详细目标与引用；成功返回时滚动到选择区域。失败明确显示“暂无可选主题”。采用时重新核对主题任务所属会话与当前模型/游标，只填目标并清空旧候选及确认。没有自动启动付费主题分析，普通打开预览仍只读取；用户点击分析后按所选会话模型正常产生用量。

续接目标输入属于模型预览范围；改变目标清除旧候选、报告和确认。报告展示生效目标、全局任务/约束/纠正数量及逐条原文/来源，闭环状态明确标成推断。

浏览器验收必须记录每个选项在弹窗裁剪视口内的几何可见性，并保存未展开详情时的同屏截图；多主题场景断言至少2项且实际选中第二项，不能用DOM存在或只有首项的截图宣称多个可见。

模型进度每800ms读取一次，只接受匹配会话和任务ID的数据；显示当前阶段、批次进度、实际并行数、请求消耗和用时，完成后显示并行峰值。关闭弹窗中止轮询，后台任务继续，来源和配置未变时重开可接回。进度100%只表示评估工作结束，质量通过仍单独判断。

设置卡注册到官方 `settings.models.footer`。重置入口仍在会话行菜单，重生预设下拉复用 `agentPresets/list`，默认沿用原预设，broken项不可选；更改预设需重新输入短ID。恢复列表注册到 `sidebar.footer.action`，通过独立 overlay 选择事务。真实隔离演练已确认原会话行可能从目录消失，恢复不能依赖该行仍存在。输入目标短ID后才允许恢复，新代际始终先保留。

## 已验证与未覆盖

- 隔离测试覆盖备份/回退、并发输入隔离、卸载等待事务收口、进程被强制终止、隔离和恢复再次失败、原件摘要、损坏账本保全、概率灰带、体积预算、原文保留、凭证隐私、连接更新及跨域Key绑定。
- `test/check-install.ts` 在独立 `DSH_HOME` 中离线安装真实发行包，通过现有 DSH 启动随机端口实例，验证服务绑定、原生凭证保存和跨启动读取，以及真实会话文件隔离后的 RPC 恢复。只关闭本轮创建的隔离进程。
- 浏览器集成检查只操作自身target；普通检查拦截重置和凭证写入。真实演练需要显式参数与新建测试副本。
- `test/check-model-apply.ts --run` 创建短测试来源并只重置其新标记fork，真实模型与菜单选用后，独立读回种子并与报告逐字比较；同时核对来源历史与原进程。
- 单会话释放只在声明的宿主版本与布局验证过；升级后必须重跑live演练。
- 尚无独立人工标注的真实长会话质量基准；不把同一模型对自身的标签当作校准真值。
- 已完成事务不支持手动撤销；0.4.0未终结事务支持显式恢复，旧版重启记录不自动续跑。断电级持久性未验证；其他同会话标签页可能需要自行刷新。
